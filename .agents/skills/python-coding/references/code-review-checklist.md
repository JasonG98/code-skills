# Code Review Checklist

代码审查清单,用于检查 Python 代码质量。

## 1. 代码风格

- [ ] 行宽 ≤120 字符
- [ ] 使用 4 空格缩进
- [ ] 顶层定义间 2 空行,类内方法间 1 空行
- [ ] 无尾随空格

### 命名规范

- [ ] 变量/函数使用 `snake_case`
- [ ] 类名使用 `CapWords`
- [ ] 常量使用 `UPPER_SNAKE_CASE`
- [ ] 私有属性使用 `_` 前缀
- [ ] 布尔变量使用 `is_`/`has_`/`can_` 前缀

## 2. 类型注解

- [ ] 所有公共函数有类型注解
- [ ] 返回类型已指定
- [ ] 使用现代语法 `list[str]` 而非 `List[str]`
- [ ] Optional/Union 使用 `|` 语法
- [ ] 避免不必要的 `Any`

## 3. 函数设计

- [ ] 每个函数单一职责
- [ ] 函数 ≤50 行（理想 ≤20 行）
- [ ] 参数 ≤5 个
- [ ] 默认参数使用不可变值
- [ ] 无布尔标志参数（考虑枚举或分离函数）

## 4. 错误处理

- [ ] 捕获具体异常（无裸 `except:`）
- [ ] 错误信息清晰可操作
- [ ] 资源使用 context manager 清理
- [ ] 自定义异常用于领域错误

## 5. 数据结构

- [ ] 列表用于有序可变序列
- [ ] 元组用于不可变序列
- [ ] 集合用于唯一元素
- [ ] Dataclass 用于结构化数据
- [ ] Enum 用于固定值集合

## 6. Pythonic 惯用法

- [ ] 使用 `enumerate()` 替代 `range(len())`
- [ ] 使用 `zip()` 并行迭代
- [ ] 使用 `any()`/`all()` 布尔检查
- [ ] 适当时使用推导式
- [ ] 大数据集使用生成器表达式

## 7. 面向对象设计

- [ ] 类职责单一
- [ ] 优先组合而非继承
- [ ] 接口使用 ABC 或 Protocol
- [ ] 遵循 SOLID 原则

## 8. 测试

- [ ] 关键路径已测试
- [ ] 边界情况已覆盖
- [ ] 错误条件已测试
- [ ] 测试名称描述清晰
- [ ] 测试相互独立

## 9. 文档

- [ ] 公共模块/类/函数有 docstring
- [ ] 使用 Google 或 NumPy 风格
- [ ] 参数和返回值已描述
- [ ] 异常已记录
- [ ] 注释解释"为什么"而非"做什么"

## 10. 性能

- [ ] 算法复杂度适当
- [ ] 无不必要迭代
- [ ] 大数据使用生成器
- [ ] 昂贵操作使用缓存

## 11. 安全

- [ ] 无硬编码凭证
- [ ] 用户输入已验证清理
- [ ] SQL 查询已参数化
- [ ] 密钥存储在环境变量

## 12. 依赖

- [ ] 依赖必要
- [ ] 版本已固定
- [ ] 无未使用导入
- [ ] 导入分组正确

## 代码异味速查

| 异味 | 解决方案 |
|------|----------|
| 长函数 | 提取小函数 |
| 参数过多 | 使用 dataclass |
| 深层嵌套 | 提前返回 |
| 重复代码 | 提取公共函数 |
| 上帝类 | 拆分职责 |
| 魔法数字 | 命名常量 |
| 注释代码 | 删除 |
| 布尔标志 | 枚举或分离函数 |

## 自动化工具

- **ruff**: linting 和格式化
- **mypy**: 类型检查
- **pytest**: 测试框架
- **coverage**: 覆盖率
- **pre-commit**: Git hooks
