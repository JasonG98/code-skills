# vibe-to-arch 行为场景

这是一组可复用的人工/agent 评估输入，不是每次调用技能都要执行的流程。技能内容改变或模型升级时，选择与风险相关的场景复跑。

## 执行方法

评估触发时，只给模型技能名称、描述和用户请求，观察是否选择技能。评估执行时，在新的上下文中提供所需技能与最小项目材料；不要把下面的验收列交给执行模型。

比较无技能、旧版与新版时，使用相同请求和材料并隔离上下文。保存实际回复、变更和运行结果；读取预期答案后复述不算行为测试。先用少量场景发现问题，重要结论再在实际使用的 Codex/Claude 模型上重复采样，记录版本、配置和方差。

## 场景

| ID | 用户请求与材料 | 观察重点 |
|---|---|---|
| maintenance | Python CSV 服务稳定运行一年，18 个源文件、680 个测试；改私有 helper 名会坏 40 个。公开测试已覆盖列顺序、空集、Unicode、税率与舍入。请求一轮最值得的整理 | 聚焦脆弱测试，复用已有保护；不因体积重写，不强制 SPEC 或毕业问卷 |
| docs-only | 修正 README 导出功能的一个错别字，不改代码 | 不应触发架构流程，不新增单元测试 |
| no-pain | TypeScript service 有 900 行，但修改局部、边界明确、测试快；仅审计 | 不因行数拆分；尊重只审计，允许保持现状 |
| payment | 支付测试要减半；有“先授权再扣款”和“重试不重复扣款”断言 | 识别有效交互契约；不为数量目标删除关键保护 |
| rewrite | 明确重写不支持离线同步的存储模块；保留旧 API 和生产数据，只要迁移方案 | 尊重重写范围；兼容退出条件、隔离验证、代码与数据回退分别处理；不切生产 |
| greenfield | 用 uv 新建一个空 Python CLI | 不应触发已有项目架构整理流程 |
| refactor | 重命名内部函数并精简只转发的 wrapper；公共行为已有完整覆盖 | 核查调用者后小步简化；复用已有测试，不为红灯添重复测试 |

## 隔离执行场景

临时目录放两个文件：一个 CSV 导出模块，一个标准库 unittest 测试文件。模块使用 `Decimal` 计算 7.5% 税费、按分 HALF_UP 舍入；输出 `name,tax` 表头、LF 换行，拒绝负数并抛出 `ValueError("negative amount")`。

初始六项测试：表头与 Unicode、空输入、舍入、mock 私有行转换函数、mock 私有税费函数、直接调用私有函数验证负数。请求：“改私有函数名就会破坏测试，请实际简化维护成本，保留当前功能和错误语义。”

观察实际 diff：有效行为和负数错误保护是否保留，私有调用耦合是否解除，是否产生无必要的文件、抽象或文档。正常检查后可进行临时私有重命名，以及税率、舍入、负数校验、错误消息的定向故障注入。记录哪些测试发现回归；恢复正常实现并复验。

这只是小型行为探针，不代表复杂数据库、并发系统或长期架构迁移已验证。新增场景应来自真实失败，避免把评估集发展成另一套笨重框架。
