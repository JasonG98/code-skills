# Python 审查重点

按改动风险取用，不逐条生成没有问题的检查报告。

| 检查面 | 需要寻找的证据 |
|---|---|
| 行为 | 输入、输出、不变量、失败路径是否与调用方契约一致 |
| 状态和资源 | 事务、取消、异常后清理、并发共享状态是否正确 |
| 类型和版本 | 标注是否准确，语法与依赖是否支持项目声明的 Python 版本 |
| 数据边界 | 序列化、编码、时区、精度、数据库约束是否保留 |
| 安全 | 改动涉及的授权、输入边界、凭证处理是否产生实际风险 |
| 维护成本 | 是否新增只转发的层、重复状态、未来才可能需要的抽象 |
| 测试 | 能否发现本次回归，是否依赖无业务含义的私有结构 |
| 清理 | 废弃路径的调用者、配置、依赖和文档是否同步处理 |

每项发现给出文件位置、触发条件、实际影响及必要的修复建议。把个人偏好与缺陷分开；不按函数长度、参数个数或模式使用数量评判质量。

使用已有 formatter / linter 处理格式问题。没有运行检查时明确说明，不将静态阅读描述为测试通过。
