# Daily Report — 日报生成技能

## 工作流程

### 第 1 步：解析今日对话

运行解析脚本，提取今日所有项目的 Claude Code 对话内容：

```bash
python3 ./scripts/parse_transcripts.py
```

- 如果输出为"未找到任何记录"，提示用户并终止
- 脚本按项目分组输出用户消息和 Claude 回复，作为日报原始素材

---

### 第 2 步：分析并提炼内容

基于脚本输出，按项目逐一提炼以下维度：

| 维度 | 提炼方法 |
|------|---------|
| **主要任务** | 用户发起了什么工作，完成到什么程度 |
| **技术决策** | 选择了什么方案，为什么 |
| **产出物** | 创建/修改了哪些文件、写了哪些代码 |
| **问题与解法** | 遇到了什么阻碍，如何解决的 |
| **待办** | 明确提到但未完成的事项 |

---

### 第 3 步：计算输出路径

```bash
# 确保日报目录存在
mkdir -p ~/Desktop/日报

# 计算本周文件名（ISO 周次）
python3 -c "
from datetime import date
d = date.today()
year, week, _ = d.isocalendar()
weekday = ['一','二','三','四','五','六','日'][d.weekday()]
print(f'文件名: {year}-W{week:02d}.md')
print(f'日期: {d.strftime(\"%Y-%m-%d\")}（周{weekday}）')
"
```

---

### 第 4 步：生成两版日报内容

按以下模板生成内容，**两版都必须生成**：

---

#### 📋 详细版模板

```markdown
## 📋 详细日报 — {YYYY-MM-DD}（周{X}）

### 工作概览
（1-3 句话总结今日整体工作方向和进展）

### 各项目记录

#### 🗂 {项目名}

**主要任务**
- {任务描述，说明完成状态}

**技术决策**
- {决策内容}：{原因或背景}

**产出物**
- {文件/功能/文档名称}

**问题与解法**
- 问题：{描述}
  解法：{描述}

**待跟进**
- {未完成项或下一步}

（如有多个项目，重复上述结构）

### 今日复盘
（2-3 句话，说明今日亮点、不足、或值得记录的经验）

### 明日计划
- {根据今日待办推断的下一步行动}
```

---

#### 📝 简洁版模板（可直接作为 commit message 或站会发言稿）

```markdown
## 📝 简洁日报 — {YYYY-MM-DD}

**完成**
- {关键事项，动词开头，一句话}

**决策**
- {重要决定，一句话}

**待办**
- {下一步具体行动}
```

---

### 第 5 步：写入周文件

将生成的内容追加到周文件末尾。

**判断逻辑：**
- 如果周文件不存在：先写入文件头 `# 日报 {YYYY-WXX}`，再写入今日两版报告
- 如果周文件已存在：直接在末尾追加今日两版报告

**追加格式：**

```
（已有内容）

---

{详细版内容}

---

{简洁版内容}

---
```

写入后，告知用户文件路径，例如：
> ✅ 日报已写入：`~/Desktop/日报/2025-W13.md`

---

## 注意事项

- 对话内容可能包含代码、错误信息等，提炼时关注**意图和结果**，不要照搬原文
- 如某项目对话较少（<3 条消息），可合并到"其他"或略去细节
- 简洁版每条不超过 30 字，详细版每个项目不超过 200 字
- 如果今日对话跨越多个不相关领域，各项目独立成节，不强行归并
